# 可选本机文字模型：独立部署、启停与回滚

本文描述当前源码的接入方式，不代表已发布安装包已经包含它，也不把自动化测试当作真实模型效果测试。**真实桌面启动、模型问答与显存释放仍需按本文验收；结果以对应版本的验收报告为准。**

## 先弄清它能做什么

当前接入的是 `Qwen2.5-1.5B-Instruct` 的独立 Transformers 服务，不是 Ollama，也不是连接 LLM-Twin 的 Gradio 页面。它只供任务级的 `assistant`（智能体文字回答）使用，包括简短产品指导和基于已选材料的问答。

- 默认模型、全局备用模型、Embedding、检索规划、论文分析、翻译、视觉阅读和生图配置保持各自原有用途；不能把此本机服务选成这些任务的模型。
- 本机回答失败不会自动改用云端备用模型。界面会说明失败，或返回明确标注的检索摘录；摘录不等于模型成功作答。
- **不是全流程离线模式。** 搜索、论文下载、其他云模型任务仍可能联网。如果单独启用了云端 Embedding，智能体检索阶段也可能把问题和材料发送到该服务；希望仅在本机检索时，应关闭该可选配置并使用 BM25。
- 只接受文字，不支持图片、流式响应或模型工具调用。它不是大模型全文分析的等价替代品。

## 与 LLM-Twin 隔离，但仍共享硬件

部署需要为 ScholarNova 准备独立的 Python 运行环境和模型文件副本，不能把配置指向 LLM-Twin 的环境、模型或缓存目录。服务不导入 LLM-Twin 代码、不读取它的配置、不加载它的 LoRA，也不向原项目安装依赖或写入模型文件。不要把“运行环境的独立副本”理解为任意虚拟环境目录复制后都能直接运行：应先验证目标 Python 与依赖确实能独立使用。

磁盘与依赖隔离不等于显存隔离。两个应用仍使用同一块 GPU、内存和 CPU；尤其只有 6 GB 显存时，**不能承诺两个模型同时运行而互不影响**。本机服务加载前会检查空闲内存与显存，显存不足就失败，不会自动结束其他程序，也不会悄悄回退到 CPU；其他程序随后分配显存仍可能造成竞争。

使用 LLM-Twin 前，可以先在 ScholarNova 设置中停止本次本机服务，或退出 ScholarNova。它只结束自己启动并持有的模型进程，不按 `python.exe` 等进程名批量结束程序，不杀端口现有进程。请勿为了释放显存而随意结束其他 Python 任务。

## 安装包里有什么

桌面构建仅附带本机服务的 Python 源码（`resources/local_inference/`）和启动控制代码，**不包含模型权重、独立 Python 环境或本机凭证**。普通 ScholarNova 功能不因这个可选功能而要求安装 Python；仅启用本机模型时需要额外准备这些资源。

独立环境需具备 FastAPI、Uvicorn、PyTorch、Transformers、Accelerate、Safetensors、psutil 等服务依赖；CUDA 是否可用取决于该环境及机器驱动。模型目录需要完整的 `model.safetensors`、模型配置和分词器文件。服务只读本地文件，不自动下载缺失模型。

## 两份设置，各管一件事

第一份是桌面私有启动配置 `local_model.json`，放在 ScholarNova 的用户数据目录。Windows 默认是 `%APPDATA%\scholarnova-desktop`；测试专用用户目录与正常目录不是同一份配置。不要把它放进仓库。

下面仅为结构示例，路径必须换成实际独立部署的位置，令牌必须替换后才可把 `enabled` 改成 `true`：

```json
{
  "enabled": false,
  "python_path": "E:\\ScholarNova-local-runtime\\python\\python.exe",
  "model_dir": "E:\\ScholarNova-local-runtime\\models\\Qwen2.5-1.5B-Instruct",
  "token": "REPLACE_WITH_YOUR_OWN_RANDOM_LOCAL_TOKEN",
  "port": 8766,
  "runtime_dir": "E:\\ScholarNova-local-runtime\\cache"
}
```

| 字段 | 要求 |
| --- | --- |
| `enabled` | 只有布尔值 `true` 才启用；文件缺失或未启用时不启动模型 |
| `python_path` | 独立 Python 可执行文件的绝对路径，文件必须存在 |
| `model_dir` | 独立模型副本的绝对目录，必须存在 |
| `token` | 单独生成的随机令牌，至少 32 个可打印 ASCII 字符，无空白；不要使用云 API Key |
| `port` | 1024–65535 的整数，默认 8766；只监听 `127.0.0.1` |
| `runtime_dir` | ScholarNova 专用缓存及临时目录的绝对路径，可自动创建；建议放在空间充足的数据盘 |

未指定 `runtime_dir` 时会使用用户数据目录下的 `local_model_runtime`。模型缓存、Torch 缓存与临时文件均放入此独立范围，不借用 LLM-Twin 缓存。使用示例中的 E 盘前，请确认该盘存在且有足够空间。

第二份设置在应用的“设置 → 任务级模型 → 智能体”：

1. 提供商选择本机文字模型 `local`，不改默认云模型或其他任务。
2. 地址使用 `http://127.0.0.1:8766/v1`；如启动配置换了端口，此处同步修改。
3. 模型名为 `Qwen2.5-1.5B-Instruct`。
4. 本机服务凭证填写与 `local_model.json` 中完全相同的独立 `token`，保存并测试连接。

桌面启动配置决定“是否启动模型进程”，任务级配置决定“智能体把请求发给谁”，两者不会自动互相改写。它们都含私有认证信息；不要提交到 Git、打进安装包、贴到截图、Issue 或共享日志。现有配置不是系统钥匙串加密存储，备份也需要保护。

## 启动、停止和看状态

启用配置后，桌面获得单实例锁才启动自己的服务；没有配置时维持原有行为。设置页的本机服务控件可查看状态、启动或停止本次服务。

- **进程已启动不等于模型已就绪。** 权重可能仍在加载，需要“测试连接”确认能回答。启动失败、模型加载失败及进程退出请检查日志。
- 停止只影响本次进程，不修改 `enabled`、任务路由或云端配置。停止后智能体仍指向本机模型，不能回答时不会转云；再次启动可恢复。
- 下次打开桌面仍按 `enabled` 决定是否自动启动。要长期禁用，退出应用后把该字段设为 `false`。
- 端口已占用时不会接管未知服务，也不会再加载第二个模型；先确认占用者并由你决定是否关闭，或更换空闲端口。
- 没有空闲自动卸载功能。长时间不用时可手动停止，退出桌面也会停止本应用持有的模型进程。

## 长问题、等待与计量边界

当前服务上下文为 2048 token，输入（含聊天模板）与预留输出合计必须容纳其中。服务默认输出 256 token、上限 320；应用网关将本机输出限制在最多 256 token。这不是“2048 个汉字”的承诺，实际长度由分词器计算。

智能体本机模式只选择最多 2 个证据片段，每段最多 500 字符；保留最近 2 条历史消息，每条最多 200 字符。当前问题不会为了凑预算被悄悄截断；超出实际 token 上限会失败并提示缩短材料。输出达到长度上限时也会标记失败，不把截断句冒充完整答案。

一次仅处理一个生成请求，不排队；忙碌会返回错误。服务生成预算默认 90 秒，应用本机回答通常有 75 秒上限，产品指导 60 秒、引用修订 45 秒；连接测试目前另有 15 秒预算。慢机器、模型未加载完成或同时测试可能导致连接测试失败，不等于配置必然错误。取消不是瞬间打断 GPU 算子，短暂忙碌需要等待。

成功响应按实际输入和输出 token 计数，输出包含结束标记；请求尝试数、收到响应数与取得 token 计量的次数分别记录。失败或超时若没有返回 usage，应用不能据此知道已经计算了多少 token。此本机计数不是云服务账单。

## 日志与故障定位

日志位于用户数据目录的 `logs` 子目录：

- `local-model.lifecycle.log`：配置错误、启动、退出、端口冲突。
- `local-model.stdout.log` 与 `local-model.stderr.log`：模型加载和运行错误。
- `backend.stdout.log` 与 `backend.stderr.log`：应用后端问题。

常见顺序是先确认独立路径和完整模型，再看端口占用、依赖导入、内存/显存，最后核对任务级地址和凭证。服务日志会遮盖启动配置中的令牌，接口状态也不返回路径或令牌；分享前仍应人工检查日志中的本机用户名、路径和其他私有内容。

## 源码测试与打包边界

不必为了每次测试重建完整安装器。开发者可在仓库根目录用独立测试用户目录启动 helper，服务根目录必须指向该仓库的 `backend`：

```powershell
node desktop/local-model.cjs "E:\ScholarNova-local-test-profile" "E:\实际仓库路径\scholar-agent\backend"
```

这是开发工具，不会把源码自动更新进已安装桌面；两个示例路径需替换，测试目录中也需单独配置 `local_model.json`。请勿一边启动这个 helper，一边让桌面再占用相同端口。结束时按 Ctrl+C，helper 只结束自己启动的子进程。

桌面源码单元测试可在仓库根运行：

```powershell
node --test desktop/local-model.test.cjs desktop/main.test.cjs desktop/security.test.cjs desktop/proxy.test.cjs
```

这些测试不加载真实权重。真实验收还应分别确认：短问答、选材问答、超长输入拒绝、失败不转云、停止后的进程/显存释放、重启恢复，以及 LLM-Twin 文件和进程未被修改或结束。单次 Python 问答成功不能代替安装版桌面验收。

若要把本轮前端、后端和桌面改动一起用于桌面测试，需要重新构建前端、打包后端，并生成包含 preload 和 `resources/local_inference` 的桌面目录；可以先做 unpacked 目录测试而不生成完整安装器。实际更新安装目录前先退出应用并备份，避免混用旧后端、新前端及缺失的资源文件。详细构建步骤见 [桌面发布说明](desktop-release.zh-CN.md)。

## 回滚

临时释放资源：在设置中停止本次本机服务，或退出 ScholarNova。永久停用：退出应用，将私有 `local_model.json` 的 `enabled` 改为 `false`；如果还要恢复云端智能体，再明确选择之前的 assistant 提供商和对应凭证，不需要改视觉或其他任务。

回退应用代码时使用已核对的同版本资源备份，不直接覆盖或删除用户数据库、知识库和模型配置。独立运行环境与模型副本可先保留；只有确认不再使用且路径确属 ScholarNova 后才自行清理。整个回滚不要求改动或卸载 LLM-Twin。
