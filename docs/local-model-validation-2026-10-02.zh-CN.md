## 本轮实际遇到的阻碍

1. 本机服务加载时检测到空闲系统内存不足，明确报出 `Insufficient free system memory for this local model` 并退出。测试期间空闲内存约 2.5–3.2 GiB；当前 CUDA 加载前的保守检查要求约 3.63 GiB，运行环境导入和桌面程序还会占用内存。建议测试前留出约 5 GiB。未绕过检查、关闭其他用户程序或自动切到云模型。
2. NSIS 安装器构建需要补充下载构建资源，TLS 连接中断，因此没有生成安装器。成功产物仅为 `win-unpacked`，不是安装包，也不是已发布 Release。
3. 当前机器上的原安装版仍为 1.2.5。本轮没有覆盖原安装目录，也没有把真实用户配置切换到尚未验收的本机助手。

真实问答脚本未通过，因此本轮不提供推理速度、回答质量、引用准确率或显存释放成功等结论。页面启动检查也不代表五个板块的完整业务功能已全部验证。

## 隔离边界

ScholarNova 的运行环境、模型副本与缓存位于独立的 `D:\ScholarNova-local-runtime`；测试使用单独配置和数据库，不借用 LLM-Twin 的运行进程、配置或缓存。原项目模型仅用于只读复制和一致性校验。没有修改 LLM-Twin 代码、模型文件、依赖或服务设置。

独立目录不隔离 GPU、内存和 CPU。两个项目仍共享同一台电脑的资源，不能保证两个模型同时运行时互不影响。服务只结束 ScholarNova 自己持有的进程，不按进程名或端口清理其他程序。

## 下一轮验收顺序

1. 保证足够空闲内存，在独立测试配置下启动本机服务，确认带凭证的健康检查成功，而不是只看端口或进程存在。
2. 通过 ScholarNova 任务测试与智能体接口验证产品指导、连续追问、基于材料的带引用回答，并核对真实 token 用量及未使用云回退。
3. 验证超出上下文限制时明确报错，停止和重新启动能工作，停止后自有进程与显存占用确实释放。
4. 备份原安装目录与用户配置，再更新本地桌面；只调整 `assistant` 任务，保留其他模型配置。通过真实桌面测试后再将本机模型标为可用。
5. 网络恢复后完成安装器构建与检查，再决定发布标签和 Release；不提前声称 Windows 安装器或 macOS 版本已发布。

配置、能力边界与回滚方法见[本机模型说明](local-model.zh-CN.md)。
