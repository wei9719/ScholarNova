# 1.2.8：从“有板块”到“能完成研究任务”

日期：2026-10-03。当前为源码与本地候选版改进，不是已发布安装器更新。

## 这一轮解决什么

按实际研究流程验收各个板块：用户进来要做什么，操作后得到什么，结果能不能接着使用。优先打通“整理资料 → 分类问答 → 形成研究计划”，暂停 Zotero 连接优化，不加载本地模型，不修改 LLM TWIN 或用户模型配置。

这些需求来自项目使用过程中的具体反馈：多个研究方向不能混在一起，研究要求不能写了无效，保存不能丢正文，资料多于一页仍要找得到。这里的“业务”指研究者实际完成的任务，不代表已有企业合同或商业订单。

## 每个板块的用途与验收标准

| 板块 | 用户要完成的任务 | 应交付的结果 | 本轮处理与后续验收 |
| --- | --- | --- | --- |
| 首页 | 找到开始入口，理解使用顺序 | 进入搜索、知识库或智能体 | 检查启动入口；不新增展示性模块 |
| 搜索 | 从研究问题找到可阅读的文献 | 有出处的候选论文、耗时及来源状态 | 搜索栏测试改用真实组件，覆盖重复提交、空输入、繁忙状态；学术源实测见前轮报告 |
| 论文详情与分析 | 理解方法、实验与局限 | 区分全文和摘要覆盖的分析，可保存为知识 | 保留现有解析与证据逻辑；真实长 PDF、视觉质量仍需专项验收 |
| 知识库 | 按方向积累、检索、更新笔记 | 能再次找到并使用的资料 | 修复只有前 20 条可见的问题；全库关键词查询、分页、出错重试；逐条删除，取消不完整的分类批量删除 |
| 知识研究分析 | 比较指定材料，形成研究思路 | 回应用户目标的可审阅分析 | 用户要求进入主模型和架构判断；分类可继续加载；跨分类选择不被清空；最多选择 50 条 |
| 研究路线 | 保存计划、回看依据、继续制图 | 完整文字、研究要求、关联知识与后续图表 | 不再自动写入前 200 字；用户确认后保存全文；关联知识按 ID 获取，不受第一页限制；路线列表可翻页 |
| 智能体 | 对某个方向的材料连续提问 | 当前范围内的证据回答 | 每个对话独立选择资料分类；知识和已关联 PDF 在查询前限定范围；切换范围不沿用旧上下文 |
| 设置 | 选择可用模型并了解连接状态 | 功能按任务配置调用模型，失败有原因 | 不更改用户 Key 或现有模型；本轮不新增厂商配置，不把连接成功等同全流程通过 |
| Zotero | 可选文献管理工具联动 | 导出到用户选择的集合 | 本轮暂缓；不作为完成其他研究流程的前置条件 |

## 关键修复为什么有用

### 研究要求会真正进入后续操作

“研究目标与约束”不只是界面文本。后端分析和架构判断都收到同一要求。保存时把要求、完整分析和所选知识 ID 一起留下；以后再生成路线，模型继续读取这份已保存草稿。草稿是研究计划，不是论文原文证据，不把预期效果写成已经做出的实验结果。

路线草稿送入模型最多取前 12,000 字，超出时明确标记；关联知识仍是摘要式摘录。这是在有限上下文中延续研究目标，不是宣称模型已读完整文献库。

### 保存有明确的确认动作

分析结束先供用户检查，不自动创建路线或知识卡片。点击“保存为研究路线”后，保存完整分析及来源关联。模型未完成、旧缓存没有来源 ID 时，不把结果包装成完成的研究路线。

保存未确认时保留内容并提示先核对路线列表，避免把网络失败误解为“服务器肯定没保存”。离页与晚到响应也应按同一原则处理。上游笔记被删除后，已保存的路线正文不随之消失，详情页会显示缺失来源。

### 对话分类和资料范围分开

文件夹用于整理对话，资料分类用于限制问答内容，两者不自动绑定。选择“食品保鲜”时，检索只使用该分类知识和通过知识条目关联的论文片段，不自动混入交通研究或无分类映射的 Zotero 结果。

分类切换后，旧消息可以继续阅读，但新请求不再发送这些旧消息；从 A 切到 B 再切回 A，也不会偷偷恢复第一次 A 的上下文。分类被删除或暂时读取失败时保留当前范围，不擅自扩大成全部资料。默认“全部资料”沿用原行为，旧对话不会被清空。

这个范围用于组织个人研究，不是多用户权限系统。现有检索候选仍有上限（知识 80 条、论文片段 600 条）；范围过滤在上限之前执行，但不能保证大库中的每条资料都被检索到。

同一范围内每轮引用编号也可能重排。发送历史回答给模型时，把旧编号标为“历史引用，非本轮来源”，并要求重新核对本轮证据；不会修改已保存的历史内容。这减少编号误用，但尚未实现跨轮来源身份追踪，用户追问“上一条 S1”时仍需核对文章标题。

## 一套可以实际操作的测试案例

建议使用单独的验收笔记，不混入正式研究结论。模型操作会按你当前设置调用供应商。

1. 在知识库创建“食品保鲜”和“交通研究”两类条目。给两个方向都写上“预测、模型、比较”等相同关键词，检查是否真正按分类区分，而不是只靠关键词。
2. 食品分类准备 21 条测试笔记。翻到第二页，能找到第 21 条；搜索只出现在最后一条中的特有词，也应找到它。
3. 进入研究分析，展开食品分类并加载更多，选中第 21 条和另一个方向的方法笔记。展开其他分类不能抹掉原选择。
4. 填写“只比较草莓保鲜的实验设计，不训练预测模型；列出尚待验证的指标”，开始分析。检查回答是否回应目标，并区分计划与实测事实。
5. 分析完成时路线数量不应自行增加。确认内容后点击保存，打开路线，检查尾段、研究要求和来源关联仍完整；刷新后不应再次自动保存。
6. 在路线中继续生成分析与图表，核对目标是否仍为保鲜实验，不能无故变为模型训练任务；模型或出图失败应显示实际失败阶段。
7. 智能体新建食品对话，选择“食品保鲜”资料范围，问“这些材料支持哪些保鲜方法比较”。再切到交通范围提问，旧回答仍可见，但不能作为新范围证据传给模型。
8. 提问“你能做什么”，检查走产品指导而不是乱查论文；输入无效内容时应可修改后重试，不应整页空白。等待回答时切换会话，检查结果与错误归属原会话。
9. 删除一个已关联知识条目，再打开路线。正文应仍在，失效来源应提示缺失，而不是显示其他不相关知识。
10. 在搜索页对同一关键词重新搜索；离开搜索再进入时，临时论文分析不应冒充新一次搜索的结果。用户主动保存的知识与对话不应被一起清除。

## 仍需继续验证的项目

- 真实模型完整任务链：长 PDF 与图表理解、证据引用、路线生成与制图，需要逐阶段记录耗时、失败和用量。
- 检索速度：前轮 GLM 查询规划耗时与短等待预算不匹配；Semantic Scholar 匿名请求出现 429，仍需按源治理和实测。
- 大资料库：现有候选上限与逐条知识压缩意味着召回不完整，应通过固定问题集测漏检，再考虑索引优化，不能只看回答流畅度。
- 图表质量：结构校验只能保证格式和结构约束，不能保证科研内容正确或达到专业人工制图水平。
- 安装发行：新版源码与旧版安装包区分；Windows/macOS 正式候选仍需独立构建、启动检查和对应源码，签名、公证与真实设备验收不能由网页测试代替。

下一轮按这些真实问题继续验收，而不是增加更多没有后续用途的面板。
