# 1.2.10 真实业务验收与修复

日期：2026-10-03。对应 1.2.10 源码，尚未发布该版本桌面安装包。

## 这次实际测了什么

经用户授权，使用其已配置的云模型，通过正式后端业务接口运行真实请求，而非仅测试连接。检索规划、翻译、文字分析、知识整理和推荐使用 GLM-5.2，科研助手使用硅基流动 Qwen/Qwen3.6-27B，视觉使用 GLM-4.6V-Flash，图像使用 SenseNova U1 Fast。没有把其它模型的输出冒充千问或 ImageGen。

数据库、上传材料和生成文件使用独立验收目录；模型配置只读入内存，逐轮校验原配置未改变，不复制密钥到报告或仓库。第一份公开论文下载使用了产品默认的系统临时 PDF 缓存，后续测试使用隔离副本；没有清理用户缓存、改动真实知识库、启动本地模型或修改 LLM-Twin。Zotero 按要求暂不测试。

这是生产 ASGI 接口、真实外部模型和学术数据源的业务验收，不是已安装桌面软件的完整点击测试，也不是多机器负载测试。模型回应、图像内容和持久化结果分别核验，HTTP 200 不等于所有子任务通过。

本轮共 **38 次文本模型请求尝试，34 次完成、4 次 HTTP 429；另有 2 次图像生成完成**。文本服务商共报告 **50,573 Token**，包括修复前后的有目的复测，不包括此前报告中的 12 次短文本探测。图片与失败请求没有完整账单信息，不能用这些 Token 推算总费用或把缺少用量视为免费。

## 并发实测：解决一处本机卡顿

同一台 Windows 电脑，两轮分别运行 6 项业务、最多 3 项同时执行：2 次产品帮助、2 次翻译、1 次证据问答、1 次知识分析。每轮实际包含 7 次文本模型调用，均完成；峰值模型 HTTP 在途请求为 3。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 六项业务总耗时 | 55.800 秒 | 33.686 秒 |
| 业务 P50 | 13.319 秒 | 9.895 秒 |
| 业务 P95（仅 6 个样本） | 29.396 秒 | 20.702 秒 |
| 事件循环最大迟到 | 15,945 毫秒 | 2,594 毫秒 |
| 健康检查最大等待 | 6,101 毫秒 | 89 毫秒 |
| 健康检查失败 | 0 / 46 | 0 / 131 |

定位到模型客户端初始化：离线假 Key、无网络情况下，原构造约 6.79 秒，重复加载 4 次证书；代理发现本身约 0.0001 秒。修复为每个客户端加载一次正常信任库，放到 2 个工作线程中，最多容纳 4 项加载工作。同一个客户端及其代理连接共享该 TLS 上下文，未关闭证书校验，未禁用系统代理或用户 CA。

取消等待不会提前释放仍在工作的槽位，也不会留下迟到构造的 SDK 客户端。这里的前后数据是各一轮小样本，包含模型响应波动和首次加载成本；不是长期吞吐、极限用户数或供应商 SLA 承诺。修复后仍有约 2.6 秒的首次运行迟到，后续还需优化冷启动。

## 长论文：不要让可选表格步骤拖垮正文

从真实检索结果选取 TimeSformer 论文，通过 arXiv 下载 8.7 MB、13 页 PDF。初次业务返回“仅摘要”，实际不是没有全文：本地逐阶段检查发现正文 62,734 字符约 1.6 秒即可提取，但结构化表格识别花了约 48.3 秒；全解析约 50 秒，超过在线 30 秒等待时限。

同时发现表格代码调用了不存在的 `extract_rows()`，本应使用 `Table.extract()`，导致已找到的表格也被丢弃。

修复后在线路径先返回正文、页码、章节和图注，不执行不可中断的全页结构化表格扫描；保留页文本中可提取的表格文字，并明确提示行列关系需回原页核对。显式离线结构化提取仍可使用 `PDFParser(extract_tables=True)`，沿用同一个 PDF 工作线程。没有通过延长超时或并发调用 MuPDF 来掩盖问题。

同一文件修复后本地解析约 1.72 秒，62,734 字符、50 章节、8 图注保留，连同 3 个图表页面渲染约 3.73 秒；送入模型的文字仍有 48,000 字符上限，界面明确披露节选和表格限制。

完整业务复测 **43.44 秒**，视觉模型实际接收文字节选和 **3 个图表页面**，报告 **17,716 Token**，不再回退成仅摘要。复测复用了本轮下载的隔离 PDF 副本，因此不能把与初次请求的耗时差全部归因于解析优化；解析阶段的 50.0→1.72 秒来自同一文件的独立离线计时。

**原文交叉核验没有全部通过。** 方法、先时间后空间的顺序、相关公式和五个数据集有正文依据，但答案把图 8 的 t-SNE 特征嵌入可视化说成注意力可视化；也混合了 TimeSformer 默认版的低计算量和 L 版的最高准确率，没有清楚区分变体。其“SSv2 低于卷积模型”概括过宽，且没有遵守 400 字要求。因此此项只判“全文与图像输入链路恢复”，不能判论文解读质量完全通过。下一阶段需要限定回答范围、核对图表编号与版本条件，并评估事实支持度，而非只检查引用编号是否存在。

- 桌面生命周期/代理/安全单测：**45 通过**；打包相关单测：**18 通过**。合计 **1,313 项离线测试通过**，不与真实请求次数混算。
- 版本检查：6 个版本文件统一为 1.2.10。锁定桌面构建环境中的 HTTPX SSL 工厂和两家 SDK 默认客户端接口存在；此项只核对兼容性，不等于重新构建安装包。
- 本轮没有重新完成桌面原生点击、Mac 实机、签名安装或发布验收；上轮 1.2.9 的桌面冒烟记录不能冒充本轮安装包结果。

## 本轮修复范围

- 产品帮助支持由进度、下一步和表达要求组成的复合追问；含真正研究内容的句子仍进入证据问答。
- 指代式研究追问补入最近用户研究主题，最多 600 字符；不把历史 AI 回答当证据，不改变当前分类和来源开关。
- 视觉模型失败时说明“已提取图表但模型未完成读取”；不再误报 PDF 没有图片。界面改为“已分析 PDF 文字”，不把节选说成完整阅读。
- 模型连接证书加载离开事件循环，保留 TLS 和代理安全语义。
- 在线 PDF 以正文和图注为先；修正表格 API，并为超时提供明确说明。

## 仍需解决

1. **检索相关性**：保护完整题名，正确编译 arXiv 短语和布尔条件，让 AI 规划的主题要求真正参与召回和筛选，不用弱相关结果凑满数量。
2. **出处核验**：OpenAlex 的 DOI/PDF 是聚合记录提供的值，不能自动保证为原论文出版标识。应保留版本和来源冲突，并核对题名、作者、年份与稳定标识。
3. **视觉可靠性**：本次真实看到智谱 1305 服务过载。同一模型后续能完成，但不能保证每次成功。账户额度、权限和使用窗口错误不应统一当瞬时限流；本轮未重写全部 429 策略。参考[官方错误码](https://docs.bigmodel.cn/cn/faq/api-code)。
4. **复杂表格**：在线路径暂不恢复可靠行列关系，复杂表格仍应结合原页/视觉复核，不能把表格文字提取宣传成完整表格理解。
5. **分析质量**：公开论文中仍有图表类型误读、模型变体混用和输出过长。接入全文和视觉是必要输入条件，不是消除幻觉的保证。
6. **体验与交付**：图像排版、冷启动、更多真论文和长会话需要继续验收；本轮没有新发布 Win/Mac 安装包，也没有升级用户正在使用的软件。

## 可重复的人工验收

使用独立资料分类，先导入一份有权使用且内容已知的 PDF，分析一个仅正文可回答的问题和一个仅图片可回答的问题；核对覆盖提示、模型尝试与答案。保存分析到知识库，重新打开，再用该分类问结论、追问局限，最后换空分类检查是否拒绝串资料。

帮助对话依次发送“我该如何使用你？”和“我已经找到论文了，下一步怎么做？不要再重复软件介绍。”，确认进入模型指导，而非文献材料不足。研究路线保存后只触发一次生成，分别检查文字、架构图、路线图和重开后的内容。

同时执行翻译、问答和知识分析，观察服务是否仍可响应；不能因为请求返回 200 就忽略模型回退、空引用、未加载的图像或不相关论文。模型实际费用以供应商账单为准，Token 与调用次数不是完整费用。
