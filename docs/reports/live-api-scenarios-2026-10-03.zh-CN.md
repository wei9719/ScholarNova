# 真实 API 与全场景测试记录（2026-10-03）

## 本轮结论

现有 GLM、千问配置均完成了真实文本请求，但还不能据此判定“所有功能可交付”。本轮做了 12 次有用量记录的模型调用、4 个学术数据源的单次检索，以及本机 Zotero 只读连接检查。发现的主要问题是模型响应慢、Semantic Scholar 匿名限流、Zotero 未连接，以及知识库研究分析的一处需求传递缺口。

源码基线为 `9ef496c`（1.2.7）。本轮只添加测试工具、测试及报告，没有修改模型设置或发布新安装器。未加载本地模型，未修改 LLM TWIN，未导出私人论文或 Zotero 条目。

## 1. 真实调用和消耗

原始记录：[模型请求](live-api-probe-2026-10-03.json)、[外部集成](integration-probe-2026-10-03.json)。JSON 时间使用 UTC，本文日期按北京时间。

| 配置 | 实际请求 | 输入 Token | 输出 Token | 总 Token |
| --- | ---: | ---: | ---: | ---: |
| 智谱 `glm-5.2` | 7 | 1,304 | 160 | 1,464 |
| 硅基流动 `Qwen/Qwen3.6-27B` | 5 | 272 | 112 | 384 |
| 合计 | 12 | 1,576 | 272 | 1,848 |

12 次均收到正文和服务商用量，结束原因均为 `stop`。没有自动重试、模型切换或限流返回。Token 是服务商返回的用量，不等于账单金额；实际费用以两个平台账单为准。

每次要求最多输出 128 Token，关闭思考模式，外部等待上限 45 秒。测试读取现有配置并验证配置文件未改变。所有提示均为合成材料，不含用户论文、密钥、账号或个人资料。

## 2. 学术数据源与 Zotero

通过生产数据源适配器检索同一个公开标题 `Attention Is All You Need`，每源最多取 5 条、不重试。沿用当时的代理环境，没有修改系统网络。

| 集成 | 真实结果 | 说明 |
| --- | --- | --- |
| Crossref | HTTP 200，5 条，20.825 秒 | 前 5 条未命中完全相同标题；接口可达不等于精确查准 |
| OpenAlex | HTTP 200，5 条，13.517 秒 | 前 5 条包含完全相同标题 |
| Semantic Scholar | HTTP 429，0 条，6.478 秒 | 此探测未加载到该源 Key，实际为匿名请求；记录共享冷却，没有绕过限流 |
| arXiv | HTTP 200，5 条，4.300 秒 | 前 5 条未命中完全相同标题；本轮未单独评价排序 |
| Zotero 本地 API | 连接失败，2.598 秒 | 不能访问本机 23119 服务；未尝试导入、写入或更改文件夹 |

本轮四个学术源各发出一次真实请求，没有以缓存命中冒充联网成功。Semantic Scholar 的冷却控制可避免重试风暴，但不能保证匿名额度可用。Zotero 失败也不能单凭此结果判定程序未安装或配置损坏，应先确认软件启动和“允许此计算机上的其他应用程序与 Zotero 通讯”设置。

“真实模型短任务”是经过生产 LLM 网关的真实调用；“离线回归”以隔离数据和模拟上游验证业务控制；两者均不等于整个桌面流程的真实端到端验收。

| --- | --- | --- |

完整 PDF 视觉分析、真实知识库 RAG、完整研究路线和制图尚未做本轮付费端到端验证。不会将“模型会回答相似提示”记成这些功能通过。一次研究路线请求可能触发多次文本和图片调用，不能用页面请求数代替计费请求数。

## 4. 已发现的改进项

1. **模型等待预算与实际延迟可能不匹配。** 当前检索规划单模型预算为 5.5 秒，规划整体为 12 秒；本轮 GLM 检索词短请求为 15.682 秒。它提示 AI 规划可能来不及完成就进入规则兜底，但本轮没有直接跑这一业务链路，不能据此计算其失败率。应比较快速模型、更小提示和端到端预算，而不是一律延长等待。
2. **回答速度尚未达到顺滑交互。** 千问短任务最高 23.290 秒，接近助手单模型 25 秒预算；GLM 短分析达到 37.822 秒。下一轮应记录首字时间、排队时间与完整结束时间，再验证流式反馈和不同任务的模型分工。
3. **检索可达和结果准确必须分别验收。** Semantic Scholar 匿名 429 仍是实际限制；Crossref/arXiv 前五条未精确命中标题，要继续核对查询语法与排序策略，不能只看返回条数。
4. **知识库研究分析忽略用户补充要求，已离线复现。** `knowledge.py:565–584` 的正常模型提示只使用知识条目，没有包含 `AIAnalyzeRequest.query`；异常兜底却使用了它。隔离复现输入“只研究低温草莓保鲜，禁止提出交通流预测”，请求字段被接收、假模型返回完成，但捕获的模型消息中既没有用户要求，也没有独特测试标记；知识条目正常传入，网络请求为 0。这会影响“只研究某方向、排除某方法”等需求，尚待修复。本轮不把复现成功计作功能验收通过。
5. **输出格式仍需应用校验。** 模型可能输出带围栏 JSON、非标准来源标记、超出字数的文字。应用必须进行解析、引用校验和可理解的失败提示，而不是把原文直接视作合格结果。

## 6. 复现边界

`backend/scripts/benchmark_live_api.py` 需要显式 `--live`，固定最多 12 次文本请求、总并发最高 3、零重试、无模型 fallback，只允许已配置的智谱与硅基流动 HTTPS 端点。不会自行切换到新供应商，也不会下载本地模型。

`backend/scripts/probe_integrations.py` 同样需要显式 `--live`，只做公开学术检索和 Zotero 本地只读检查，不调用生成模型。两者的 `--runtime` 必须指向希望验证的配置目录，运行工作目录也应选该目录，避免误读源码目录 `.env`。

输出需要指定新的 `--output` 文件，禁止覆盖已有报告或写入所选用户数据目录。报告不保存 Key、配置全文、私有文献或原始 HTTP 错误正文。失败时停止下一阶段升压；已经安排的本阶段请求（包括排队请求）仍会完成。超时也可能发生计费，不能将缺少返回用量解释为免费。

进一步付费测试应先确定总额度，并对真实出站调用统一计数，包含 fallback、引用修复、视觉和制图。当前 12 次已完成；在明确下一批费用边界前，不自动扩大付费调用。
